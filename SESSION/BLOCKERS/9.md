## 2026-09-26T00:00:04Z `lib/cluster.ts` returns `undefined` cell size at zoom 14, which turns clustering off
- blocked on: `lib/cluster.ts:12-17` and `lib/cluster.ts:37`
- symptom: `cellSizeForZoom` returns `undefined` for `zoom >= 14`, and `clusterMarkers` then passes every item straight through as an individual point. Separately, line 37 does `items.find((item) => item.id === group.ids[0])!` inside a `.map()`, which is O(n squared), roughly 1.2 million comparisons per re-cluster, and the effect re-runs on every `moveend`.
- why i cannot fix it: `lib/**` outside my namespace belongs to sessions 1 to 8, and my ALLOWED list names only `components/ananta/**` and the component files.
- proposed one-line fix: keep a cell size at every zoom instead of returning `undefined`, for example `if (zoom >= 14) return 0.01;`, and replace the `items.find` with the coordinates already accumulated on the group (`group.lngSum / 1` for a singleton).
- severity: blocker
- what I did instead: `components/map.tsx` caps the records it hands to the clusterer at `MAX_MARKERS = 250` and states the cap on screen, so the freeze cannot happen from the UI. That is a caller-side guard, not a fix, and it will hide a genuine density problem once the catalogue grows.
