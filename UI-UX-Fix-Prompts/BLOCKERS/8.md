## 2026-09-27T02:10Z the radar's progress bar needs a static inline width, which is a deliberate exception
- blocked on: `components/ananta/stress-radar.tsx` (my own file, recorded for the reviewer)
- symptom: the spatial contract bans inline transforms and the quality gate bans transitions on width, and neither forbids a static `style={{ width }}`. The bar is a value channel, so it cannot become depth, which leaves a length encoding. A Tailwind arbitrary utility cannot express it because Tailwind extracts class names at build time and cannot see `w-[${score}%]` computed at runtime; the JIT output would not contain that class and the bar would render at zero width with no error. An inline width is the only correct way to render a length from a runtime value with zero dependencies.
- why i cannot fix it: it is not a defect, it is a documented trade. Recorded so a reviewer does not read the inline style as a contract violation.
- proposed one-line fix: none. If session 4 ever exposes a static width scale (for example twelve `w-*` steps at 10 percent each), swap the inline width for a lookup on a rounded score and the exception disappears. That is a real option rather than a hypothetical, and it costs a small table.
