## 2026-09-27T02:05:00Z `motion.state` had to change, and nine sessions import it
- blocked on: `components/ananta/tokens.ts`, the `motion` export
- symptom: the previous round shipped `state: "transition-all duration-200 ease-out"` and `hover: "transition-colors duration-100 ease-out"`. The spatial contract bans `transition-all` outright, because it also transitions `box-shadow` and a five layer stack repaints every frame. `transition-colors` is also out, since only `transform` and `opacity` may transition. And `duration-100` is no longer a ratified duration: section 4 fixes hover at 120ms and adds 320ms for a scene change.
- why i cannot fix it: this one is fixed, and it is my file, so no action is needed from anyone. It is recorded because the value changed underneath nine importers.
- proposed one-line fix: already applied. `hover: "transition-transform duration-120 ease-out"` and `state: "transition-transform duration-200 ease-out"`. `transition-transform` covers transform, translate, scale and rotate, all of which are compositor only, so it satisfies the constraint without naming a forbidden property. Any session that wanted a colour fade needs `transition-opacity` alongside it, not `transition-colors`.
- severity: degraded

## 2026-09-27T02:06:00Z `perspective` and `preserve-3d` ended up on two class names, and the contract names one
- blocked on: `app/globals.css`, the `.stage` and `.stage-3d` rule
- symptom: the contract says `preserve-3d` on `.stage` only. I first wrote it that way, then found session 4 had already adopted `.stage-3d` in six places: `app/explore/page.tsx:352`, `components/ananta/explore/exclusion-panel.tsx:75`, `components/ananta/explore/result-card.tsx:70`, `components/discovery-search.tsx:82` and `:104`, `components/travel-options.tsx:61`. A container that has no perspective is not a 3D container, so those six call sites were rendering flat.
- why i cannot fix it: `components/discovery-search.tsx`, `components/travel-options.tsx` and `components/ananta/explore/**` are session 4. I will not edit their files to rename a class.
- proposed one-line fix: already applied, and it is the smallest thing that works. One rule, `.stage, .stage-3d { perspective: 1200px; perspective-origin: 50% 40%; transform-style: preserve-3d; }`. Two names, one declaration, so the six call sites work today and the contract's actual intent, never on a card, is what the guard enforces. Session 4 or session 3, when the tree is quiet, collapse the two names to `.stage` and delete the alias. `lib/ui-guard/spatial-primitives.test.ts` allows `.stage` and `.stage-3d` and fails on any other holder of `preserve-3d`.
- severity: degraded

## 2026-09-27T02:07:00Z The six shadow stacks are written twice on purpose, and a guard test keeps them honest
- blocked on: `app/globals.css` `:root` versus `tailwind.config.ts` `theme.extend.boxShadow`
- symptom: the same five layer stacks exist as `--shadow-z-*` custom properties for the `.depth-*` classes, and as `theme.boxShadow` for the `shadow-*` utilities. That is a duplicated map, which is the exact bug class `.opencode/skills/ananta-bug-catalog` files under "computed but discarded and duplicated maps". A one-sided edit would leave a card whose CSS shadow and Tailwind shadow disagree by a layer, and nothing else in the build would notice.
- why i cannot fix it: not a blocker, a decision. Recorded so nobody "fixes" the duplication by deleting one copy.
- proposed one-line fix: already applied. Both copies are needed: the custom properties are what `.depth-raised` reads, and the theme entries are what `shadow-raised` reads, and a Tailwind utility should not depend on stylesheet load order. `spatial-primitives.test.ts` imports `tailwind.config.ts` and compares all six resolved values against the custom properties after whitespace normalisation, so a drift fails the build. `card` and `float` are aliased to `raised` and `floating` so the 22 existing `shadow-card` and `shadow-float` call sites pick up a real stack with no edit to another session's file.
- severity: cosmetic
